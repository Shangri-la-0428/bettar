# AI 抱石定线原型开发前置文档

日期：2026-10-14 · 文档包版本：0.1 · 状态：实施准备稿

**第一版要做一个可以看图讨论、检查局部问题、反复修改的定线研究原型。** 它使用一面预置墙和一批合成岩点，生成两到四个手部动作的短段，比较规则方法与 Codex 协同设计。先在电脑里把流程跑通，再决定下一轮投入。

## 2 一分钟理解系统

| 谁在工作 | 做什么 | 使用方式 |
|---|---|---|
| 产品负责人 | 说清想要的动作，比较方案，提出修改 | 当前对话＋浏览器查看器 |
| 规则程序 | 根据动作模板批量尝试点位、朝向和接触组合 | 本地 Python 工具 |
| Codex | 提出设计思路、修改候选、调用相同检查工具 | 当前对话，不先接 API |
| 检查程序 | 查库存、安装边界、点位冲突和简化人体姿态 | 输出分项报告和求解依据 |
| 浏览器 | 显示墙、布点、动作步骤和问题 | TypeScript＋Three.js，导入结果包 |

典型过程是：我们提出横移要求 → 程序或 Codex 给出候选 → 程序检查 → 浏览器看图 → 我们提出修改 → 创建新版本并重算。

规则程序单独就要能生成候选。Codex 的作用通过同条件对照来判断，不能把所有效果归功于大模型。

## 3 已沿用的方向与本包默认值

沿用前期讨论：以抱石为起点；固定板是同一底层问题的受限版本；扫描和识别后接；一个人配合 Codex；先文档再实现；不把模型自评当真人效果。

本包提出以下实施默认值，方便进入具体讨论：

- 一面 3 米乘 3 米的平面墙，16 个合成岩点，两套合成骨架。
- 三种局部动作情境，每段两到四次手部换点，脚步单独记录。
- 先做只读查看、比较和反馈；布局通过数据文件与当前对话修改。
- 使用同一数据格式表达固定点位与自由摆点；逐步放开位置、朝向等变量。
- 第一轮先做确定性几何检查和简化姿态求解。力学、连续动作和真实等级未检查时明确标出。

这些默认值用于缩小实验，不是已测得的运动规律，也不是用户逐项确认的产品承诺。相较战略稿，最主要的收敛是：**把简化受力研究从首轮必交项移至 P1，避免它阻塞最小工作循环。** 姿态求解仍是 P0；若无法完成，则报告阶段成果和未完成项。

## 4 第一版怎样算完成

我们能打开一份示例，看到至少两个通过全部 P0 检查的不同候选，逐步检查动作与问题，改变一个条件后得到新结果，并对比修改前后。软件要正确区分通过、违反、无法判断、未检查和结果过期；P0 通过仍不代表真人可攀。

另有一份规则生成与 Codex 协同的实验记录。结论可以是大模型有帮助、没有帮助，或目前证据不足；软件验收不以大模型必须胜出为条件。

前期提到的 1–2 周是约 10 个集中工作日的探索预算。第一次复盘看表示、求解和候选质量，之后依据实际困难调整；不以日期代替验收。

## 5 开始开发前的决策

当前只交付文档，没有开发原型、安装 Blender、训练模型或发布内容。文件内已给出足够具体的默认方案，不需要产品负责人逐项选择程序库或算法参数。

下一步只需要围绕一个产品问题对齐：**先接受“可看、可改、能做局部几何检查”的研究原型，再通过结果决定是否投入完整动作与力学评价。** 如果第一版必须直接预测真实 V 级或独立保证可攀，就需要扩大数据、验证与人员条件，不能沿用当前预算。

本包以 PRD 管功能范围，以技术方案管数据与状态，以实验文档管验收；场景文件提供测试输入。发现冲突时先统一约定再实现，不凭单个示例覆盖共同规则。
