# 实验与验收方案

日期：2026-10-14 · 状态：开发前约定，尚未实施或取得实验结果

依据：现有战略 v0.2 与本轮收敛范围。本文的预算、样本数与阈值是工程起点，不代表统计功效计算或科学证明；05 文档提供身材与情境预置，骨架、端点及容差契约以 02 技术设计为准。

## 1. 验证的问题与结论边界

软件验收回答：本地工具能否正确读取输入、生成候选、执行已实现检查、呈现证据并导出可复查记录。研究比较回答：在相同条件和预算下，Codex 的策略与修改建议是否改善模板搜索的结果或成本。软件可验收而 B 组没有优势；不得为了证明 AI 有用而修改门槛。

全部使用合成资产：3 m × 3 m 垂直墙，另设 10° 仰角变体；库存共 16 个独立实例，包括 6 个 jug、4 个 directional_edge、6 个 foothold。身材是预置假设，输出不标真实难度、V 级或真人可攀率。三个情境为“脚先移动再抬手”“侧拉横移”“脚点重定位”；每段包含 2–4 次手移动，脚步单独计数。情境名称表达设计意图，不代表力学已经实现。

固定板参照锁定库存安装位置和朝向，允许选择接触点与顺序；自由摆点组在同一库存及墙面条件下解锁位置和朝向。两种模式分别报告，不能把设计变量增加造成的收益归给模型。

## 2. 检查结果如何解释

P0 检查 schema、库存引用与数量、请求及状态序列符合性、固定布局锁定、整个安装包围区域的边界、按预置保守包围体计算的装点冲突，以及简化骨架在每个接触状态的 IK 解、接触残差和关节范围。数值容差、求解步数、重启次数须在运行前固化。

每项仅用四种状态：`pass`（满足已实现检查）、`fail`（有明确违反依据）、`unknown`（已尝试但不能确定）、`not_checked`（尚未实现）。IK 未收敛、超时或数值异常均为 `unknown`；只有足够保守的可达上界等硬证据可以直接判 `fail`。未知项不计通过。

所有 P0 项为 `pass` 才标“已实现几何检查通过”。这只说明找到离散接触姿态解，不说明状态之间存在真实可完成的动作。受力、摩擦、完整人体碰撞及连续／动态转换属于 P1，P0 报告和查看器必须持续显示 `not_checked`，不输出“整体可攀通过”。动画插值不新增证据。保守包围体冲突也可能淘汰真实可安装方案，报告须保留此假设。

## 3. 对照、预算与固定输入

| 项目 | A：模板＋搜索 | B：相同工具＋Codex |
|---|---|---|
| 候选来源 | 预设动作模板、固定搜索与局部修改 | 同样模板与工具，加策略选择、参数和布局修改建议 |
| 提供的资料与工具 | 场景、知识卡、人体预置、检查说明及工具 | 提供同样材料与工具；模型预训练知识不是受控变量 |
| 评价权限 | 调用冻结评价器 | 同左；不得自行给候选判通过 |
| 成本 | 程序时间、评价次数、人工准备 | 同左，另记对话、工具调用及模型用量 |

先准备 6 个开发实例和 6 个保留实例，每组覆盖三个情境，每情境有固定板／自由摆点一对实例；同对使用相同墙角、身材、库存与初始布局，仅改变可解锁变量。两种墙角和身材在三对中分配，不宣称覆盖全部交互。保留集使用未参与调参的组合，避免仅改 ID 或排序形成近重复。输入与预期在开发前存档；保留实例的结果仅在冻结后统一打开。当前 Codex 可能参与生成合成实例，所以它们不能被称为模型从未见过的独立外部测试。

每轮只运行一个 6 实例集合；每实例采用 3 个程序随机种子，每次最多评价 5 个候选，即每臂最多 90 次候选评价、两臂最多 180 次。评价包括失败、重复和修改后的候选；每次评价内部的 IK 计算预算一致并另记。B 每轮最多 3 批策略／修改对话，批量驱动 CLI，避免逐点反复调用。没有候选时允许提前结束，剩余预算不转移给另一实例。

程序种子不使大模型输出可重现。保存 B 的输入上下文、可见模型信息、完整建议、结构化修改及实际生成文件；通过重放这些文件复查评价，不宣称重新提问会得到相同答案。token 或费用不可取得时留空并注明原因，不估填为零。

冻结内容包括场景、库存、人体、情境约束、容差、排序规则、搜索／IK 预算及代码版本。修正评价器缺陷时建立新版本，保留旧结果并同批重跑 A/B；已经看过的保留集转为回归集，新的研究比较另建保留集。不得针对单个候选放宽条件。

## 4. 验收测试表

下表中的正反例使用明确构造的几何事实及手算边界，不以同一个生成器或评价器输出充当唯一正确答案。

| ID／功能 | 输入或操作 | 预期结果 |
|---|---|---|
| AC01／F01 | 合法最小文件；缺字段、未知 schema 版本、非有限数、单位错误 | 正例可读；反例拒绝并定位字段，不能自动猜测修复 |
| AC02／F01、F04 | 合法库存子集；不存在 ID、重复占用同一实例、数量超限 | 前者通过；后三者明确失败 |
| AC03／F04 | 整个安装包围区域在边界内、恰在容差边界、中心合法但边缘越界 | 符合冻结边界规则；越界失败，报告测值与阈值 |
| AC04／F04 | 包围体分离、明确相交、刚好接触 | 分别按冻结冲突规则判定；保留最近距离或交叠依据 |
| AC05／F04、F05 | ① 提交已知合法姿态做 FK 复核；② 仅给对应目标接触，按不同于已知解的冻结初值及预算调用 IK | ① 验证器确认骨长、关节及残差；② 求解器返回可独立 FK 复核的解。两者都通过才完成本项，不用已知姿态冒充求解输出 |
| AC06／F04 | 双手间距超过双臂加肩宽的保守最大上界，计入端点偏移及接触容差 | 明确失败；依据人体参数给出上界，不依赖 IK 恰好失败 |
| AC07／F04 | 模拟求解超时、达到迭代上限、数值异常 | `unknown`，不计通过，也不声称证明不可达 |
| AC08／F04、F05 | 每个状态可求解但未检查转换 | 仅姿态几何通过；受力、碰撞、转换仍为 `not_checked` |
| AC09／F02、F03 | 同实例分别运行 A/B，达到预算或生成失败 | 保留每次尝试及原因；不越预算，不用成功样例替换失败记录 |
| AC10／F01、F04、F07 | 删除已用库存点；旋转方向点；切换身材或墙角 | 旧结果标过期、重新评价；旋转更新接触坐标／朝向，不能声称难度变化 |
| AC11／F07 | 仅重排输入字段／库存顺序；用冻结候选重复评价 | 规范化内容一致，确定性检查一致；数值结果满足冻结容差 |
| AC12／F01、F07 | 截断 JSON、缺资产、哈希不符、过期评价器、外部路径或可执行内容 | 拒绝／隔离且说明原因；旧结果不能作为当前通过，导入不执行代码 |
| AC13／F05、F06 | 导入两个候选，在同一相机视角切换对比并查看动作步、反馈后导出 | 相机不跳变；位置、朝向、接触、状态和未知项对应；反馈不改计算结论 |
| AC14／F07 | 导出后重新导入；改变文件内容后再校验 | 前者身份与内容哈希一致；后者检测变化并使关联评价失效 |
| AC15／F01、F04 | 固定板模式沿用位置／朝向；擅自改动位置或朝向 | 前者通过锁定检查；后者明确失败，不能静默转为自由摆点 |
| AC16／F01、F02、F04 | 合法接触引用／允许肢体、事件与前后状态一致、满足指定起终点及 2–4 次手部换点；反例为不允许的肢体接触、未到指定终点、请求 3 次实际 2 次、单事件偷偷改变另一肢体 | 正例通过；反例均明确失败并定位请求、事件或状态。初始接触和释放不计换点，脚步另记；只检查序列合法性，不证明动态可行 |

AC01–AC16 均需留记录。演示集至少提供 2 个非重复候选通过全部已实现几何检查，可来自任何一臂，不要求所有请求成功。无解、未知和错误输入也必须可展示。这是研发完成门槛，不是对研究胜负的要求。

同一请求内，非重复采用合成工程默认：先按模板及几何属性匹配等价岩点，忽略 ID、名称和数组顺序；去掉不改变接触的重复状态后，满足以下任一条件才计新候选：至少一处安装位置相差 ≥ 0.05 m，安装角度差 ≥ 15°，或实际手脚接触事件序列不同。旋转对称岩点的等价朝向不计差异；交换等价实例 ID 不计差异。这些门槛在比较前冻结，仅用于去除微小扰动，不代表真人体验或统计独立性；姿态求解初值不同也不单独计新设计。

## 5. 报告与 5 分钟用户验收

每臂报告请求数、实际候选数、非重复候选数、各检查状态、找到首个几何通过候选的评价次数／耗时、人工改动和对话成本。按情境、模式、身材分别列小样本结果；不得合并为真人成功率。一个候选因多项失败可重复出现在原因表，分母必须注明。B 更优、持平、退步或无法判断均是可接受研究结果；无独立现实观测时，不下定线质量或身体适配结论。

用户浏览验收建议约 5 分钟，下列分段只计查看与操作；CLI 计算等待暂停计时并单独记录，不承诺一分钟出结果：

1. **0–1 分钟**：导入演示包，确认墙、16 个库存实例、身材假设与所有未检查项。
2. **1–2 分钟**：在同一相机视角切换两个候选，逐步查看手移动与独立脚步，检查一个姿态证据。
3. **2–3 分钟**：在当前对话提出减少库存或旋转一个点；Codex 操作 Python CLI，计算完成后继续计时，用户导入新结果，对照旧版过期标识。前端只查看、导入、比较、反馈和导出，不执行 Python 或调用模型 API。
4. **3–4 分钟**：导入一份已知越界文件和一份 IK 未确定结果，确认明确失败、未知与未检查没有混淆。
5. **4–5 分钟**：导出并重新导入；核对版本、哈希、检查状态和 A/B 成本记录。CLI 若超时，保留实测耗时及未知状态，不把预先结果冒充现场计算。

完成后记录用户是否能解释“几何通过仍未证明动作成立”，以及哪一步需要额外说明。该脚本验证可理解性与流程完整性，不替代后续真人试爬。
