# AI 抱石定线原型 PRD

日期：2026-10-14 · 版本：0.1 · 状态：实施准备稿

第一版让我们在电脑里设计一小段抱石线路，查看具体布点与手脚接触方案，发现部分问题，并比较不同设计方法。使用者是产品负责人和当前 Codex；暂不依赖合作岩馆或专业定线员。

## 1 产品目标

使用已知的墙和岩点，完成一次“提出要求 → 生成候选 → 程序检查 → 看图比较 → 修改再检查”的工作循环。交付可操作的本地研究原型，检验它是否值得继续做成定线工具。

第一版回答三个问题：

1. 我们能否用同一份数据准确表达墙、岩点、布局和多种动作解法？
2. 程序能否发现明确的几何问题，并说清楚检查范围？
3. 加入大模型以后，找到合适候选的质量或成本有没有改善？

“目标 V3”“平衡风格”可以作为设计意图保留，但第一版不输出预测 V 级或声称已验证风格。可交付的数值是点间距离、关节角、位置改动量等；真实难度与趣味需要后续真人反馈。

## 2 一个具体使用过程

产品负责人说：“用这批点做一段向右横移，先安排脚步，最后右手到终点；给我两种方案。”

Codex 将要求整理成结构化请求。规则生成器尝试不同布局与接触顺序，程序检查库存、安装区域、岩点冲突和简化人体的姿态。Codex 可以读报告、提出另一种思路、再调用相同工具。

我们在浏览器导入结果包，切换候选，旋转岩壁，点选某个岩点，逐步查看手脚接触和身体姿态。看到“第 3 步没有找到姿态解”时，能定位到该步骤，并知道这是当前求解结果，不能直接理解成真人一定爬不了。

产品负责人提出“把第二个手点往左移一点”。Codex 创建新版本并重新检查；浏览器对比新旧版本。任何修改均不能继续沿用旧版的通过标记。

第一版的生成与修改由当前对话配合本地脚本完成。浏览器负责查看、比较、反馈和文件导入导出，不设置一个实际上不会工作的“自动调用 AI”按钮。

## 3 第一版范围

| 项目 | 默认范围 |
|---|---|
| 墙面 | 3 米宽、沿墙面高 3 米的单一平面；首例垂直，10° 仰角用于变化实验；安装区域距墙边留 0.2 米 |
| 岩点 | 16 个合成库存实例：6 个大把手、4 个有方向的边缘点、6 个脚点；同一个实物实例不能重复占用 |
| 动作 | 脚先移动再抬手、侧拉横移、脚点重定位三种情境；每段 2–4 次手部移动，脚步另记 |
| 布局模式 | 固定点位中选线；或在同一批点上放开位置和朝向。共用数据与检查器 |
| 人体 | 两套合成骨架参数，用于敏感性对比，不代表具体人群能力 |
| 方案数量 | 在预设演示案例上展示至少 2 个通过全部 P0 检查的不同候选；其他请求无候选时明确说明原因 |
| 使用环境 | 本地电脑与桌面浏览器；合成数据和静态资源均随原型提供 |

以上尺寸、数量、情境是控制工作量的设计默认值，未经过真人校准。固定板和自由摆点共享人体运动与接触规律，先固定部分条件，再逐步增加设计自由度。

本轮不纳入照片识别、扫描、真实库存识别、整条长线路、复杂折面、动态跳跃、脚钩动作、精细手指、自动定级、账号协作、云部署和蓝牙点灯。Blender 与模型 API 均不是首轮依赖。

## 4 功能要求

P0 是本版必须完成的内容；P1 根据第一轮结果再决定。

| 编号 | 功能 | P0 具体行为 |
|---|---|---|
| F01 | 场景与请求 | 提供预置墙、库存和人体配置；请求包含动作情境、起终点条件、长度、锁定项与允许变化项；未知属性允许标为未知 |
| F02 | 规则候选 | 不调用大模型也能用模板和搜索生成候选；记录随机种子、预算、候选总数与淘汰原因；不保证每种请求有解 |
| F03 | Codex 协同 | Codex 读同样的输入，提出布局或策略修改，使用相同检查工具；保留修改及理由；禁止为某个候选单独放松验收条件 |
| F04 | 分项检查 | 检查格式、库存、起终点与动作序列是否符合请求、安装边界、保守包围体冲突、同一骨架的接触姿态与关节范围；显示通过、违反、无法判断、未检查四种结果 |
| F05 | 三维与动作步骤 | 提供旋转缩放、正视图、点位编号、安装朝向、接触区域；逐步查看左手右手左脚右脚；只有求解成功的姿态才显示为计算结果 |
| F06 | 比较与反馈 | 在同一视角切换至少两个候选，显示点位变化、检查差异；选择方案并记录原因；导出反馈文件 |
| F07 | 保存与复现 | 导入与导出版本化结果包；关联请求、场景、人体、生成器和检查器版本；输入变化后旧评价失效；保留原始候选和派生版本 |

P1 可包括简化静态受力求解、连续动作轨迹、精细碰撞、拖拽编辑和专用小模型。它们各自需要检查假设和验收，不能以“后面会做”代替 P0 的真实状态。

## 5 页面和操作

只做一个工作页面，主要区域是三维岩壁。侧边显示场景条件与候选列表，底部是动作步骤，检查详情按需展开。先保证文字、编号与状态清楚，避免完整编辑器带来的额外工作量。

| 操作 | 界面响应 |
|---|---|
| 打开示例或导入包 | 显示墙、库存摘要、场景版本和候选；数据不兼容时保留原画面并说明错误 |
| 选择候选 | 切换布局、动作步骤与该候选自己的报告，不混用其他方案的结果 |
| 点选岩点或问题 | 高亮对应点、接触或步骤；显示编号、位置、朝向及问题说明 |
| 上一步或下一步 | 展示接触变化与求解姿态；没有姿态解时显示接触示意和“当前未找到姿态” |
| 对比方案 | 保持相机位置，标出移动、旋转、更换的岩点和评价变化 |
| 写反馈并导出 | 保存候选版本、主观意见和期望修改；没有实际尝试的意见不得记为试爬记录 |

不默认播放平滑人体动画。关键姿态足以帮助讨论，补间动画即使后来加入，也只能作为示意。

## 6 结果怎样表达

| 显示文字 | 含义 |
|---|---|
| 在当前假设下通过 | 某项已实现的检查满足条件；注明是库存、包围体或姿态检查 |
| 违反已检查条件 | 有明确证据，例如库存重复、安装超界；简化包围体冲突须写明它是保守近似 |
| 当前无法判断 | 求解未找到结果、超预算或条件缺失，不能写成“不可能攀爬” |
| 尚未检查 | 该能力未实现，例如动态过渡、摩擦抓握、完整身体碰撞或真实难度 |
| 结果已过期 | 布局、人体或检查器改变；旧结果只作历史记录，当前显示需重算 |

P0 没有“整条线路可爬”总勾选，也没有综合难度分。每个姿态找到解，仍不代表人能完成姿态之间的转换。

## 7 完成标准

功能完成与研究成功分开判断。原型完成须满足：

- F01–F07 在预设演示案例中完整走通，至少两份通过全部 P0 检查的不同候选能查看和比较；差异判定规则见实验文档。
- 展示一次库存或边界错误，以及一次姿态无法判断，系统能正确解释。
- 修改位置、朝向或人体参数后生成新版本，旧结果失效，新报告关联正确。
- 规则方案与 Codex 协同方案各有同条件实验记录；若协同没有改善，也如实交付。
- 有启动、示例、限制说明和结果导出；不需要安装 Blender、接入 API 或取得真实岩馆数据。

具体测试和实验规则见[实验与验收](03-experiment-and-acceptance.md)。

## 8 尚待实际验证的产品假设

我们假设“具体布点＋动作解释＋局部检查”会比只提供图片更容易讨论；假设少量带属性的合成岩点能暴露关键表示问题；假设大模型能在某些案例上减少修改次数。这些是假设，不是第一版必须做出的正面结论。

原型先控制在约 1–2 周集中探索预算内。若姿态求解仍不可靠，先交付几何工具与失败证据，再决定下一轮范围；不能用手工摆一个好看的身体冒充算法结果。

技术细节见[技术与数据方案](02-technical-design.md)，具体案例见[场景与动作卡](05-scenario-and-movement-cards.md)。
