# 第一版交付与验证

本文保留第一版历史验收；竞赛与训练板扩展的当前能力和边界见 [项目说明](../../README.md)。

2026-10-14。Beta Atelier 已能在本机网页完成：生成候选 → 查看岩点与手脚状态 → 检查 → 修改岩点 → 重新检查 → 比较和保存。

## 如何体验

服务运行时打开 [本机工作台](http://127.0.0.1:5173/)。重启方式见 [项目说明](../../README.md)。无需 Blender、模型 API 或账号。

首次打开载入真实计算过的示例。选择某个岩点，调整位置或安装角并保存，再点击重新检查；旧修订可以保留和对照。结果包需要主动导出，页面刷新不会自动恢复未导出的草稿和反馈。生成和检查的原始运行快照另存于 `.runtime/runs/`。

## 已实现的范围

| 项目 | 当前能力 |
|---|---|
| 场景 | 3 × 3 m 简单墙面，0° / 10° 仰角 |
| 岩点 | 16 个合成实例：6 个大把手、4 个方向边缘点、6 个脚点 |
| 动作 | 脚先行、侧拉横移、脚点重定位；2–4 次手移动，脚部动作另外记录 |
| 人体 | 两组固定骨长的合成人体；共享躯干、关节约束与多初值数值求解 |
| 生成 | 规则模板和受限变化；每组默认 3 个候选，尚不是通用定线生成器 |
| 检查 | 数据、库存、起终接触与动作顺序、固定布局、安装边界、岩点包围体、手距必要条件、逐状态姿态求解 |
| 编辑 | 点击或下拉选择岩点，输入位置和旋转角；创建新版本再检查 |
| 查看 | 三维旋转缩放、正视图、步骤切换、身体接触状态、同视角比较 |
| 保存 | JSON 结果包、导入一致性校验、设计反馈 |

网页生成按钮使用规则算法。Codex 可在当前对话提出方案变化，再由同一套程序检查。未接入自动调用大模型的生成服务。

与准备稿相比，按用户最新要求增加了本机 Python HTTP 连接层与数值岩点编辑器，使网页操作形成完整流程。前端为 TypeScript / Vite / Three.js，核心为 Python / NumPy / SciPy / JSON Schema。

## 验证结果

- **74 项引擎测试通过**：包含实际 IK、独立骨长／残差复核、明确反例、unknown 和导入数据篡改检查。详见 [自动测试报告](../../tests/RESULTS.md)。
- **12 组场景组合冒烟通过**：覆盖三种情境、固定／自由布局及两组人体和墙角配置。记录在 `fixtures/backend-smoke-results.json`。
- **9 组浏览器操作验收通过，无 JavaScript 错误**：切换候选与步骤、生成新配置、编辑新修订、失效报告隔离、真实越界失败与修复通过、重复检查不累积报告、反馈与结果包导出、损坏导入保留画面、unknown 不伪造身体姿态，以及窄屏操作。
- **前端生产构建通过**；构建有单包体积提示，当前 Three.js 主包压缩后约 142 KB。桌面 1440 px 与手机 390 px 没有页面横向溢出。
- 独立界面复核通过；手机完整截图出现工具拼接问题，另用内置浏览器实际滚动确认显示正常，未以拼接图证明验收。

浏览器记录见同目录 `browser-workflow.json` 和 `browser-capture.json`。初始示例的 3 个候选均通过已实现检查；按当前去重门槛为 **2 个非重复候选**，不能宣称有 3 种独立设计。

## 规则与 Codex 建议的首次对照

| 数据组 | 规则方案 A | Codex 建议重放 B |
|---|---:|---:|
| 开发组：6 情境实例 × 3 种子 × 5 候选 | 90 / 90 通过 | 90 / 90 通过 |
| 保留组：6 情境实例 × 3 种子 × 5 候选 | 90 / 90 通过 | 90 / 90 通过 |

每个“情境实例 × 种子 × 方案组”按当前门槛均有 2 个非重复、通过的候选；所有 5 次尝试都保留在分母中。详细记录：[开发组](development-experiment.json)、[保留组](holdout-experiment.json)。

B 是本次 Codex 提出的一项明确建议：先准备双脚，再移动手；自由布局时把目标手点下移 6 cm、目标脚点上移 3 cm。固定布局只调整动作顺序。这项建议以确定性变换重放，没有逐例调用模型，也没有可核实的单次 token 或费用记录。

**这次没有测出 AI 的额外优势。** 两组全部通过说明当前合成例子较容易，评价范围也有限。保留组仍由同一项目构造，不是独立外部验证。未据结果调整规则或建议；各组执行顺序均为 A 后 B，耗时只作描述，不作公平速度排名。

实验开始前固定引擎指纹和输入配置；执行脚本的源码快照在运行后补存，其中开发组依据工具编辑记录回建。因此此次是工程对照，不能称为预注册实验。后续脚本已改为运行前保存源码快照。非重复数量和首次通过耗时由保存的候选及评价补算，未重新求解或删除失败尝试。

## 已知限制与下一步依据

几何和离散姿态通过，不代表真人能完成连续攀爬。抓握与摩擦、受力平衡、完整人体碰撞、动作转换及真实难度均未检查。合成岩点目前只有简化外形、接触点和方向等描述，没有真实岩点抓握品质模型。人体尺寸也是工程假设。

本版首先建立可操作、可复核的研究流程。下一步应先增加能区分好坏方案的反例和接近边界的样例，找出检查器误判、候选缺乏变化的原因，再决定是否引入受力模型、更丰富的岩点和动作生成。现有结果不足以支持扩大模型训练或宣称商业岩馆可直接采用。
